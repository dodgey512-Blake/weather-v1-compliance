# V1.0 合规 天气App

> 我希望用户先看懂当地天气，再根据明确的数据和个人安排作决定。基础天气与穿衣建议免费，跑步判断只在数据足够时提供可应用的时间选择，定位和数据导出由用户主动控制。

体验入口 [合规版天气Demo](https://dodgey512-blake.github.io/weather-v1-compliance/)

设计入口 [VIS 2.0 合规版](https://dodgey512-blake.github.io/weather-v1-compliance/vis-2/)

## 1. 产品范围

1. 天气承担日常入口，OOTD Lite提供衣物类别建议，跑步是第一个完整时间窗场景。工作名称暂用天气 Weather，正式品牌和商标待确认。
2. 当前真实天气覆盖NWS支持的美国地区，默认简体中文，可在设置切换English。语言、温度单位、计划地点和时区分别保存。
3. 免费路径包括选择地点、看天气与预警、穿衣建议、一条待执行跑步计划、明确决定、应用内变化提醒和训练后反馈。主导航固定为天气、计划、设置三个Tab。16个运行页面覆盖欢迎、地点、首页、小时与三天详情、官方预警、穿衣、计划列表与编辑、判断、反馈、设置、来源、消息、报价意向、本机实验记录和情景演练。必要状态包括空、加载、部分可用、过期、失败恢复、保存失败、DST歧义、历史消息、反馈回看及演练退出。
4. 不建立登录、云同步或公开用户内容功能。当前报价仅收集本机价格意向，真实商店订阅、付款和广告均未接入。
5. 新版使用独立Web存储、缓存与Android应用身份，可与原版分别使用。旧版地点、计划和偏好不自动迁入。

## 2. 地点与位置权限

1. 首次使用提供手动城市与主动定位两条路径，拒绝定位仍可继续手动选择。
2. 本地搜索仅匹配已有四个美国预置城市，页面说明实际可用范围。其他地点可在设备支持时主动使用近似定位，不能显示已经具备全球城市搜索。
3. 定位前说明天气用途、位置粒度、接收方和手动替代。系统授权只在用户确认后触发，Android仅请求粗略位置，不申请后台位置。
4. GPS坐标先近似到0.01度再传给NWS并保存。近似坐标仍属于位置数据，不能称匿名数据。
5. 所选地点与计划地点分别保存。浏览其他城市或切换界面语言，不改变已经建立的计划地点和当地时间。计划开始按绝对时间保存，天气、计划及消息按对应地点时区展示。夏令时重复时刻需要明确选择第一次或第二次，不存在的当地时刻要求重新选择，均不静默修正。
6. 地点解析失败、美国之外或缺少时区时如实提示，不以默认城市替换后仍显示定位成功。

## 3. 天气首页与数据来源

1. 首页先展示地点和重要官方预警，再展示天气、当地日期时间、小时趋势、当天重点、OOTD与下一条计划。
2. NWS提供逐小时天气、站点观测与官方预警。观测、预报和预警请求分开容错，不因某个来源失败丢弃其他成功结果。
3. 获取时间、原始发行或观测时间、到期时间分别展示。刷新成功不把旧观测改成刚刚观测，也不延长旧缓存的原始有效期。
4. 缺少气温、风、体感、降水概率或AQI时显示缺失，不用零值、合成天气或不相关地点的数据补齐。
5. 图表使用真实小时序列，缺失数据保留间断。免费提供24小时趋势和未来72小时详情，按地点当地日期分组，点击日概览进入对应小时。当日高低温由现有当天预报区间计算时明确口径，不冒充已测得的全天极值。内部统一保存°C、km/h及0至100的概率或缺失，按供应商unitCode转换，未知单位与未知风向保持缺失。设置提供公制与美制，切换语言不改变单位。降水概率只表达概率，动态雨滴不假称精确雨强。
6. 晴、云、雨、雷暴、雪与雾分别表达，昼夜独立。动画始终位于信息之后，减少动态时仍有可辨认静态状态。
7. 当前默认停用尚未证明商用资格的Open-Meteo免费地名与AQI接口。天气及预警继续使用NWS，AQI显示未接入授权来源。

## 4. 有效期与官方预警

1. 最新、有效缓存、部分可用、过期、缺失与情景演练分别呈现，来源和缓存方式不互相替代。
2. 预报发行时刻异常、未来发布时间、过期或空值不能被归为新鲜数据。当前实验有效期为预报获取后约1小时且受原始发行时间约束，站点观测约90分钟，预警检查约5分钟，缓存重读不续期。来源过期时保留可阅读内容并标注时间，停止应用相应旧建议。首页与OOTD共用时效选择，先使用有效观测，其次使用覆盖当前时段的有效小时预报并明确来源，两者失效则显示缺失。旧AQI两小时有效期仅属未来授权来源或演练规则，当前未启用实际AQI接口。
3. 官方预警依照实际状态、消息类型、有效期和受影响时段判断。测试或失效消息不当成当前正式预警，已取消及已到期消息不持续阻断。
4. 影响训练时段的严重预警优先于天气分数。Minor advisory也应显示具体注意事项，不能当作普通无预警天气。
5. 官方警报正文保持原文，注明语言和来源。中文界面中的解释不冒充官方中文原文，不把应用提醒当作政府紧急预警系统。
6. 数据和通知可能延迟、缺失或受系统影响，出门前应自行核对最新官方信息与现场条件。

## 5. 日常穿衣

1. OOTD Lite免费提供衣物层数、可脱卸外套、雨具、防滑鞋及遮阳类别，不推荐具体商品。
2. 建议使用有效温度或体感、降水、风、当天温差、日常场合和冷热偏好。缺少有效天气时提示刷新，不生成确定结论。
3. 雷暴等风险优先提示调整户外安排。雨衣或防晒用品不能被表述为已经消除天气风险。
4. 首页摘要与详情使用同一规则。场合提供日常、通勤工作与户外活动，冷热偏好为偏冷、中性、偏热。反馈保存在本机，透明调整后续衣物层数，当前没有自动学习或医学评估。OOTD浏览与反馈单独记录，不用于证明跑步专业价值成立。

## 6. 跑步计划与判断

1. 用户设置地点、当地开始时间、预计时长和可调整范围。开始必须尚未过去，整段结束同时受未来72小时与可用数据覆盖约束。可调整范围为固定、前后30分钟、前后1小时、前后2小时，候选开始按15分钟步长比较。训练类型仅作记录，备注不参与规则，均置于选填区域。本机保存草稿，写入失败保留输入，成功后才反馈保存完成。
2. 完整训练时段参与判断。预报或AQI未覆盖整段时不能只看开始时刻就给出可应用建议。
3. 固定时间不生成改期，其他候选必须处于用户允许的范围。没有更好的可用窗口时明确说明，用户仍可保留自己的原安排。
4. 当前真实AQI未接入，因此完整跑步评估会提示条件不足，停止应用自动改期。保留计划是用户自己的决定，不包装成天气已批准或安全。
5. 判断页展示原计划、完整训练区间、因素、候选、来源、发行时间和有效期，图表与数值对应同一快照。keep为保留、watch为关注、change为可比较改期、no-window为没有可用户外窗口、blocked为必要条件不成立。实验基线为高温30°C或体感32°C、低温0°C、风35km/h或阵风50km/h、降水概率50%。更高风险包括风50km/h、阵风70km/h、气温36°C、体感40°C、AQI高于150，AQI高于100先进入关注。雷暴、雪冰和影响时段的官方预警优先处理，Minor advisory明确提示注意事项。AQI参数仅用于演练或未来取得授权且有效的来源。内部排序为降水概率×0.4、最大风速×0.7、超过26°C部分×4、低于5°C部分×3、AQI超过50部分×0.5，不可用天气与相关预警另外加权。只有原时段有影响、候选满足全部约束且至少改善10个内部单位时才改期。规则版本为experimental-1.0-compliance，属于待美国跑者研究验证的实验参数，不包装成安全概率。任何建议都不调整路线、配速或训练负荷，也不作医疗、救援或人身安全保证。
6. 新数据到达、关键输入变化、地点编辑或确认窗口过期时，使旧建议失效。确认前精确核对计划updatedAt、snapshotId、ruleVersion、expiresAt和候选完整时段。确认层打开后条件变化则返回新判断，只有确有时间变更才出现比较确认，无需调整直接保留。保存成功只表示应用内计划更新，不等于日历、手表或付款成功。
7. 一次只保留一条待执行计划，完成或取消后离开下一次安排并停止监测。取消保留历史，单条删除需确认并反馈结果，误删恢复策略仍待生产验收。训练结束后才收集完成情况、实际体感、建议帮助程度，三项初始均未选择，缺项不能保存，保存后可回看和修改，反馈关联对应计划。

## 7. 情景演练与记录

1. 情景页独立提供晴、雨、雷暴等示例，始终显示演练标识。它使用同一规则与天气组件，不显示实时或官方状态。
2. 情景改期和反馈不修改真实计划、原始决定、真实通知或实验指标。
3. 计划记录区分待执行、完成与取消，决定区分接受候选、保留原安排和选择室内。室内选项仅在没有可用户外窗口且用户允许替代时提供，选择后取消对应户外安排，保留原先和更新后的时间及决定。每次决定保留所依据建议、规则版本、快照和时间。
4. 变化提醒由新旧快照的实际变化驱动，比较判断类别、候选窗口、降水或温度的重要变化及预警更新，不用固定概率生成冲突。已结束计划停止监测，打开已经结束或非当前计划的消息时进入对应记录，不显示另一条活动计划的结论。
5. 事件只留在本机，包含weather_loaded、plan_created、plan_edited、recommendation_viewed、recommendation_decided、weather_change_opened、outcome_saved、ootd_viewed、ootd_feedback和pricing_intent，并按本机事件保留必要关联，事件容量最多500条。当前JSON只导出脱敏摘要，不承诺完整研究备份或中央长期全量分析。核心指标以看过有效判断的真实计划为分母观察明确决定比例，再看实际执行和帮助程度，天气浏览、OOTD和报价分别计算。正式实验的去重、曝光与决定、保留期、采集授权及失败补报仍待方案，不把没有采集的留存、采纳、付费或天气准确率写成已证明结果。

## 8. 通知与监测

1. 通知按用户需要开启，拒绝后仍可在消息页看已经获得的应用内变化。
2. 当前只在应用运行期间获取和比较天气。关闭应用、系统限制或网络中断可能使检查停止，不宣传已经具备后台远程天气监控。
3. 系统权限、通知通道和用户在App中的提醒偏好分别保存。系统允许不能自动重新开启用户已关闭的偏好。
4. 设置提供关闭通知和查询实际权限的路径。Android提交通知只表示交给系统处理，不能写为已经送达或已经被看见。
5. 锁屏通知按系统隐私设置隐藏个人内容。清除本版数据时取消该版本通知和原生临时状态。

## 9. 隐私、导出与删除

1. 本项目数据包括所选地点、计划、冷热偏好、决定、训练后反馈、天气快照和本机事件。它们保存在当前浏览器或Android沙盒，当前没有账号备份。
2. 真实网络接收方包括静态托管的GitHub Pages与提供天气的NWS。请求会向相关服务传输IP和请求参数等数据，定位披露说明近似坐标会用于天气请求。
3. JSON默认脱敏，省略坐标、天气快照与来源URL、自由备注、事件属性和可能编码地点的天气标识。导出由用户主动选择，不自动上传。
4. 日历导出先说明会包含计划时间、地点名称及备注，再由用户选择保存和导入。生成ICS不等于已获得系统日历权限或已同步日历服务。
5. 清除前列明影响并确认，删除本版主记录、草稿、临时选择与缓存，同时清理原生状态。读取异常时提示并尽量保留原记录，写入失败不清空输入。网页生成下载只能反馈已准备文件，Android只有系统实际保存回调成功才显示文件已保存。缓存外壳不代表离线仍有最新天气。旧版本和同源其他应用数据保留。
6. 关闭定位或拒绝系统权限不自动删除历史数据，界面提供清除路径。清除应用数据、卸载及浏览器站点设置也可移除相应本机记录。
7. 正式发行的公司法定名称、客服及私密隐私请求联系方式待提供真实资料。演示维护入口使用项目GitHub Issues，提醒避免公开敏感信息。

## 10. 报价与未来服务

1. Running Pro价格页面仅收集自愿意向，拟定月付2.99美元、年付19.99美元。用户可选择对报价感兴趣或目前不考虑，并可以重新选择。金额属于实验报价，显示未收费状态，不生成交易、订阅或已购买权益，意向不当作真实购买、续费或收入。
2. 天气基础、官方预警、日常穿衣和一条计划继续免费。选择价格意向不改变免费能力，也不解锁尚未实现的多计划、持续监测、历史结果或经过验证的个体化服务。
3. 正式收费前接入Apple IAP及Google Play Billing，显示商店真实价格、计费周期、自动续订、试用规则、恢复购买和管理路径。
4. 当前没有广告SDK，因而未假称已完成某广告网络的同意或审批。后续接入时按真实地区、年龄、SDK和数据流完成隐私声明及适用同意。

## 11. VIS与可访问性

1. VIS沿用深蓝、暖白、天空蓝与少量荧光绿。风险通过颜色与文字同时表达，关键天气、警报和操作优先可读。
2. 正文16至17、辅助14至15、功能标签至少12 CSS px，关键命中区域至少44×44。长英文、中文多行、窄屏及短屏自然重排。
3. Liquid Glass近似主要用于导航、工具与浮层。天气正文和表单保持稳定，减少透明度后仍可辨认当前页。Tab已选页、拖动候选和活动状态独立，按住、移动、松手、取消、快速反向与页面中断均正确归位。按压约120ms、状态约200ms、页面约320ms，详细动效与控件状态以本版VIS和交互规范承接，静止导航不持续摆动。
4. 默认中文、设置内切英文。字段校验、权限、错误、来源和辅助名称同时切换，自由输入保留原样。
5. 新版VIS补充定位披露、NWS-only、AQI缺失、过期和警报状态、前台提醒、脱敏导出、删除和价格意向组件。
6. 减少动态、减少透明度、键盘、焦点和长文本纳入本轮验证。Safari真机、原生读屏和最大系统字体仍需设备验收。

## 12. Android与正式发行

1. Android采用独立应用身份com.weatherpersonal.app.compliance与本地WebView，可与原版并装。当前为测试签名演示包。
2. 原生仅在确认后请求粗略定位，近似坐标返回前再次限制精度。网络标识包含WeatherCompliance/1.0，不臆造联络邮箱。
3. WebView收窄可信来源、路径、端口和原生桥边界。文件导出限制MIME、扩展名与大小，界面和宿主同时控制敏感内容。
4. API36模拟器验证与实体设备可靠性分开记录。历史SystemUI ANR在本次复测结果中如实说明，不沿用旧版通过状态。
5. 当前没有iOS原生交付。正式商店仍需签名、AAB或iOS包、账号和协议、应用资料、年龄和国家配置、数据安全表、真实支付广告及生产审核。
6. Google Health声明按实际跑步计划与训练反馈功能判断，不能只因主类是天气就直接排除Activity and Fitness，也不将其擅自认定为医疗器械。
7. NWS使用标识、服务端缓存与监控、商业数据许可、实际客服和隐私联系人、真机和读屏构成正式发行待办。可用性测试计划招募5至8名美国目标跑者，观察首次计划完成、判断理解、明确决定和训练后反馈，尚无研究结果。后续雷达、10天预报、Calendar/Health/Garmin/Strava连接、路线或训练强度、后台远程推送和自动学习继续留在后续范围。
